# jev-poc: jev に 2048 を遊ばせる

TypeSafe AI の判定モデル [jev](https://docs.typesafe.ai/introduction) は、文章を生成せず、Choice / Score / Noul という型付きの判定だけを数百 ms で返す。この PoC は jev に 2048 を遊ばせて、次の 2 つを確かめる。

1. 反射だけで動く AI は、古典的な探索 AI と比べてどこまで戦えるか
2. 同じモデルでも、盤面の聞き方で強さはどれだけ変わるか

## プレイヤー

| 名前 | 内容 |
|---|---|
| `random` | 合法手から一様ランダム |
| `greedy` | 1 手で得られるスコアが最大の手。同点なら空きマスが多い方 |
| `expectimax` | 深さ 3 の expectimax |
| `jev-raw` | 盤面の数字だけを渡して Choice で選ばせる |
| `jev-sim` | 各合法手を打った後の盤面と特徴量を渡して Choice で選ばせる |

jev には合法手だけを選択肢として渡す。合法手が 1 つしかない手番では API を呼ばない。API が失敗したゲームは中断して記録し、ランダム手での穴埋めはしない。

## 使い方

```bash
go build -o jev2048 ./cmd/jev2048
```

```bash
export TYPESAFE_API_KEY=...   # jev 系のプレイヤーを使うときだけ必要
```

```bash
./jev2048 watch --player jev-sim --seed 42
```

```bash
./jev2048 bench --players random,greedy,expectimax,jev-raw,jev-sim --games 5 --out results.jsonl
```

- `--max-calls` で jev API の呼び出し回数に上限を付けられる(既定は watch 5000、bench 20000)。上限に達すると実行中のゲームをすべて中断し、そこまでの結果を出して終了コード 1 で終わる
- 一時的な失敗(HTTP 429 / 5xx / 529、接続エラー)は 500ms から倍々で最大 5 回まで再試行する。再試行は呼び出し回数に数えない
- `bench` は、中断したゲームが 1 つでもあれば終了コード 1 で終わる
- `--out` には 1 手 1 行の JSONL(盤面、選んだ手、確率分布、confidence、レイテンシ)を書く

### 読むときの注意

- **jev の判定は決定的ではない。** 同じ盤面・同じ質問でも確率と confidence が揺れる(素の盤面で confidence 0.43〜0.52)。そのため jev 系のゲームは同じシードでも再現しない。実際、この本番の前にシード 1 で 1 ゲームずつ回したときは `jev-raw` 2772、`jev-sim` 5944 だった(上の表では 316 と 4624)
- **5 ゲームは少ない。** `greedy` ですら 1016〜7616 と振れている。下の順位のうち `jev-sim` と `greedy` の上下は、この試行数では確定できない
- `LATENCY/MOVE` は 1 手あたりの実時間で、再試行の待ち時間を含む。今回の jev 系は中央値 215ms、95 パーセンタイル 265ms 前後、最大 1463ms だった

## 考察

**反射だけでは探索に届かない。** 平均スコアは `random` 832 < `jev-raw` 1464 < `jev-sim` 2307 < `greedy` 4046 ≪ `expectimax` 27173。jev は 2 種ともランダムよりは明確に強いが、3 手先まで読む `expectimax` とは 10 倍以上の差があり、2048 に到達したゲームは無い(最大は 512)。1 手 220ms なので、1 手 4ms の `expectimax` より 50 倍以上遅くもある。

**聞き方で打ち筋が変わる。** `results.jsonl` から、合法手の間で「その手で得られるスコア」に差がある手番だけを抜き出し、最大スコアの手を選んだ割合を数えた。

| プレイヤー | 最大スコアの手を選んだ割合 |
|---|---|
| `random` | 53%(180/341) |
| `jev-raw` | 51%(277/543) |
| `jev-sim` | 82%(513/627) |
| `expectimax` | 76%(4136/5441) |

`jev-raw` はランダムと変わらない。数字の並びだけを見せても、どの手でタイルが合体するかは読み取れていない。各手の結果を計算して見せた `jev-sim` は 82% まで上がる。「モデルに計算させず、計算した結果を見せて選ばせる」のが効く。

**それでも `jev-raw` がランダムより強いのは、方向の方針を持っているから。** `jev-raw` の 740 手のうち上は 7 手だけで、残りは左・右・下にほぼ均等。30 手目以降で最大タイルが角にあった割合は 78%(`random` は 14%、`greedy` は 52%)。指示文の「最大タイルを角に保て」を方向の好みとして実行している。`jev-sim` は下 58%・左 23% に偏り、最大タイルが角にある割合は 99% で `expectimax`(95%)を上回る。

**`jev-sim` が `greedy` に勝てていない理由の仮説。** 目先のスコアを取る割合は `greedy` の 100% に対して 82%、角は `greedy` よりずっと堅く守る。つまり「角を守る」を優先して合体の機会を見送り、盤面が詰まって早く終わっている可能性がある(平均手数は `greedy` 324 に対し 196)。ただし上の注意のとおり試行数が少なく、順位は確定していない。

**confidence は当てになる。** confidence が 0.5 以上の手番では、最大スコアの手を選んだ割合が `jev-raw` で 100%(29/29)、`jev-sim` で 98%(255/260)。0.5 未満では 48% と 70%。平均 confidence は `jev-raw` 0.30、`jev-sim` 0.47 で、情報を与えるほど自信も上がる。「confidence が低い手番だけ探索に回す」という混成プレイヤーが次の実験として筋が良さそう。
